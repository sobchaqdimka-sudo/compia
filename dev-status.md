# Состояние разработки

Обновляется при смене фазы. Источники: `git log`, актуальный код, последние диалоги.

## Реализовано

### Фаза A — Магнетичный онбординг ✅
- Промпт хоста с зеркалированием, инсайтом, провокационными вопросами, без сахара
- `detect_need` — Haiku-классификатор с явными примерами для `romantic` (нет ложных отрицательных на «хочу женского внимания», «вторую половинку»)
- Системный гейт прилетает СРАЗУ после финальной реплики хоста (без «подожди минутку»)
- Запреты: никаких имён компаньона, никаких описаний качеств, никаких рекомендаций Tinder/Bumble

### Гейт 18+ ✅
- Кнопочный, текст и кнопки на языке собеседника
- «Ещё нет» → `adult_declined_at`, автомат больше не дёргает
- Ручной `/persona → Мира` сбрасывает отказ (вторая попытка)
- Без «Дякую. Тепер поруч Міра» — Мира пишет первой сама

### Контекстный переход friend/coach → Мира ✅
- `detect_need` запускается и в friend/coach после 4+ сообщений
- Если romantic + не подтверждён 18+ → гейт после финальной реплики текущей персоны
- Если romantic + уже взрослый → прямое переключение
- Уважает `adult_declined_at` (не пристаёт после отказа)

### Фаза C — Стадии отношений и видимая память ✅
- `mira_activated_at` ставится один раз при первой активации
- `_compute_mira_stage(user_id)` → (1/2/3, days)
- `_build_mira_stage_block(stage, days)` подмешивается в `extra_system` каждого ответа Миры
- Видимая память усиливается на стадиях 2+ (Мира активно цитирует досье)

### Имя Миры — флоу фантазии ✅
- Колонки `mira_name_status` (`unrevealed`/`nicknamed`/`revealed`) и `mira_nickname`
- `detect_nickname_action` — Haiku-классификатор предложение/отказ/прочее
- `_build_mira_name_block` меняет инструкцию по состоянию
- Жёсткий запрет: «тема имени не существует пока юзер сам не спросит»

### Медиа Миры ✅
- Фото: Flux Dev (база) + Nano Banana edit (по запросу с тем же лицом)
- `screen_appearance_description` — лёгкая модерация описания внешности (не для несовершеннолетних, не реальные люди, бельё/купальник — ок)
- Тихие кружочки: Kling 2.1 i2v → FFmpeg квадрат от верха кадра
- Говорящие кружочки: ElevenLabs TTS → VEED Fabric → FFmpeg микс с чистым TTS-аудио (Fabric гадит звук, не используем его)
- Реплика для озвучки через `generate_spoken_line` (та же персона + история + досье — не противоречит чату)
- Vision на входящие фото юзера (через Anthropic image content block)

### Память и проактив ✅
- `user_facts` обновляется раз в 15 user-сообщений через Haiku, prompt caching
- Проактивные сообщения с режимами `off/rarely/sometimes/often`, не «долбит» (пишем только тем, кого помним, и только если человек ещё не вернулся)

### UI/UX ✅
- Slash-команды через `set_my_commands` с ru/uk локализацией
- `/start` — приветствие или подтверждение сброса с кнопками на языке юзера
- Реалистичные паузы между bubble: типинг-индикатор перед каждой репликой, 0.7–2.7с пропорционально длине
- Языковая директива `_language_directive` в `extra_system` (страховка от дрейфа на персидский/украинский)
- Персистентный индикатор `_keep_action` — типинг/upload-photo/record-video-note не пропадает на длинной генерации

### Анти-паттерны (постепенно фиксили в `common.txt` и `personas/*.txt`)
- Никаких асинхронных обещаний (`«подожди»`, `«сейчас будет»`, `«дальше будет интереснее»`, `«всё будет»`)
- Никаких системных внутренностей в чате (`«18+»`, `«персона»`, `«дорослий контент»`)
- Никакого gatekeeping (`«не могу»`, `«не для тебя сейчас»`, `«без объяснений»`)
- Никаких рекомендаций конкурентов (Tinder, Bumble, dating apps)
- Никаких описаний качеств других персон
- Никаких спойлеров имени Миры
